# 研究目标、验收与恢复

## 本次故障

用户案例：分析菌种—通路—钙含量—ATEC 评分的关系。原步骤程序对 `r1` 等研究要求做了多次实际检查，执行器却把重复ID当成错误；修复模型三次返回近似程序，重试没有推进。

执行器现在允许同一ID包含多项检查，按 AND 汇总并保留每条观察。未知ID、未覆盖的要求、恒真检查及失败后试图覆盖为成功仍被拒绝。失败保存异常类型、消息、已完成检查与实际输出结构。

## 按研究问题设计

`research_design` 把具体问题与分析步骤对应，明确关联、来源贡献、预测、比较或描述的证据类型。综合步骤必须通过 `Step.inputs` 真正读取各问题的结果，单独的执行顺序不代表结果已经连接。设计审核同时核对问题覆盖和解释范围。

工具只承担可复用计算。需要特定连接、综合模型或不同层数图时，仍由通用程序路径按确认方法编写。旧关联工具也声明输出表并提供统一关联字段，便于与新工具和程序组合。只消费上游结果的程序可不读取原始表；运行时只有经过归属、状态和哈希检查的表进入 `results[alias]`。

物种分层通路自带的来源标签不等于已经检验的菌种—群落通路关联。共同显著结果的交集不等于中介或因果链。不能凭空要求至少200行结果或至少若干显著特征。有效检验没有显著关系应保留为空结果，不放宽阈值或补造网络边。

## 失败后继续

- 保留成功步骤；失败只阻断依赖该步骤的后续计算，独立分支继续。
- 记录每个失败步骤，并保留可用的成功结果；失败状态不会显示为“已完成”。
- “修复并继续”只重试失败、被阻断或中断的步骤；结果顺序按步骤ID组织，不假设完成项始终是连续前缀。
- 复用前核对成功产物的哈希；损坏、丢失或依赖已失效的结果重新计算。
- 通用程序保存已尝试代码和修复状态；手动继续从最新修复版本开始。研究方法、输入版本或结果绑定变化后不能沿用其他任务的修复状态。
- 每轮自动修复仍有上限；仅修改注释或原样返回不算修复，不反复执行同一程序。模型修复失败也保留诊断。
- 需要改变研究设计时，使用“调整方案”，生成待确认的新设计；不在执行途中擅自变更目标、阈值或检验。

操作系统隔离仍是强制边界；本次没有放宽网络、文件或系统命令权限。

## 验证方式

`tests/test_execution_recovery.py` 验证独立分支继续、非连续成功步骤保留、只重试未完成项，以及综合步骤必须读取实际结果。`tests/test_adaptive_analysis.py` 验证多次检查按AND累积、失败不可覆盖、无变化修复停止、修复状态跨重试保留与隔离执行。

本地原失败运行在独立副本离线重放：191 个样本，25,961 条输入特征过滤为 9,029 条分层通路，共 18,058 项关联；原定 BH 阈值下两个表型各自显著数和共同显著连接数均为 0。新执行器一次通过验收，后续热图成功生成。原项目和原失败记录未被覆盖。

真实数据的外部模型联调未执行：自动审查拒绝向未明确授权的外部目的地披露研究数据上下文。完整模型流程改用独立随机生成、明确标记的合成数据验证；真实数据只用于本地离线重放。

最终验收：全套回归 `154 passed, 3 skipped`，最终定向检查 `33 passed, 3 skipped`；三项 OS 隔离集成另行启用，完整隔离测试 `18 passed`。前端类型检查及生产构建通过。浏览器核对了完成结果保留、修复继续和重新设计入口；界面截图使用主动注入失败的合成验收项目。

独立合成三表案例经真实模型规划、设计审核及程序生成，五步全部完成：钙—ATEC 关联、两组菌种关联、分层通路关联/贡献，以及读取前四步结果的菌种综合证据表和概览图。验收恢复了先前已生成并审核的同一合成方案，继续完成程序生成与执行，没有把模板答案或人工填写结果当作真实模型输出。运行中 dtype/检验检查及菌种键编码差异经修复后通过，并保留每次尝试的代码、检查与审查记录。

后续代码生成会接收必要的键结构与来源程序信息，修复时也能看到上游键的有限样例；这些结构信息用于明确可追溯的连接规则，不进行模糊匹配。真实项目使用外部模型时仍需按实际授权处理研究数据和上下文。
