# 项目与分析的产品流程

## 固定的四个位置

我的项目是起点。新建项目必须填写名称，可填写备注；进入项目后可编辑，不再按首个文件自动改名。

项目概览集中呈现备注、当前进度与下一步。项目文件保存全部当前材料并默认展示实际内容。开始分析包含描述研究问题和选择工具两个入口。研究成果集中呈现分析记录、图表、结果表及论文报告。

导航不随上传或运行次数不断变化。没有文件或没有成果时，所在页面提供明确的下一步，不展示模拟内容。回到首页和刷新不会自动打开旧研究。

## 上传先看内容

上传先给表格预览，默认不要求填字段字典或研究设计。内容不正确时可调整工作表、表头所在行、分隔方式、编码、文件用途、编号与矩阵方向，再预览后保存。普通表格不添加虚假的 ID 数据列。

第一版读取器支持 XLSX、CSV/TSV/TXT 与平面对象数组 JSON。文本支持 UTF-8、GB18030 和逗号/制表符/分号。一个工作簿可分别登记多个工作表。复杂嵌套 JSON、合并多级表头、PDF 和图片并不被当作已经可分析的数据；需专用适配器或用户整理。可读取不等于可以作任意统计推断。

文件页的补充背景与单列解释均选填。用户可说明记录对象、单位、编码及缺失含义，也可让模型整理成可审核草稿；没有理由要求用户逐列填写清楚的字段。

## 文件目录与本次输入分离

material_ids 记录项目中所有当前文件/工作表版本；active_datasets 保留旧接口的兼容入口。新增同类文件不从目录中消失。重新解释或映射后，新版本替换目录中的对应旧版本，旧版本仍可由历史运行引用。

本次任务通过 dataset_ids 明确绑定输入。解析器、字段画像和已保存背景形成研究上下文；规划、预检和执行读取同一批文件。多份同类表格需要决定使用范围时显式提出问题，不默认取上传最晚的一份，也不静默拼接。

新增与某任务无关的文件不会让其已认可输入被替换。删除、重新解释所选文件或更改其语义会使相应方案失效。复现、缓存和报告仍绑定确认时的文件、含义和任务设置。

## 分组只在比较任务里出现

文件页不再有全局“分组与研究设计”表单。仅当任务需要组间比较时，显示：本次哪份样本表、哪列记录组别、该列的实际取值及数量、要比较哪几个组、是否存在重复或配对观测。

study_override 记录本次任务的选择，不改写全项目的通用设置；其他任务不受影响。多份样本表造成歧义时先选择本次要用的文件。程序还检查样本匹配、组别存在性、有效样本及已声明的受试者字段，用户勾选不能绕过这些检查。两组用 Mann–Whitney / 两组 PERMANOVA；三组及以上用 Kruskal–Wallis / 多组 PERMANOVA。每组不足三个样本时阻断推断步骤，引导改为描述性组成或样本对比。

研究问题里直接点名样本编号时，规划优先走指定样本组成、样本对比或核心菌，并在 parameters.samples 写入真实 ID；不会用全体样本均值冒充那几个样本的对比。

## 方案里直接补充

研究说法对不上列名、数值没有单位，或等级顺序还不清楚时，方案停在可回答的补充项上：选择对应列、填写单位或标明单位未知、按顺序点选等级。提交后写入字段说明，并重新生成方案。补充完成且条件满足时给出可执行步骤。

规则只有一条：挡住方案的每一件事，都带着解决它的入口。方案会被三方挡住——规划模型（对研究的疑问）、分布解析（说法还没有对应的列）、程序检查（某一步的前提数据不满足）。三者都以补充项的形式出现在方案里，方案的问题列表只由补充项生成，因此不存在只能看、不能答的问题。

程序检查的补充项把回答写到它该去的地方：步骤参数（指标列、两个比较组、相关的两列）、研究设置（分组列、是否独立样本）、本次使用的文件（多份同类表里选一份）、样本对应（把丰度样本对应到样本信息里的记录，或本次不纳入）、已知限制的确认（不能校正协变量时是否按未校正继续）。这类回答不改变步骤，只重新检查，不会再问一次模型。平台确实做不了的情况（重复受试者、每组不足三个样本等），补充项是一句必填的说明，交给规划模型按说明改用能执行的步骤。新增的检查即使没有专门的入口，也会落到这一种。

模型自己提出的问题也走同一个入口。能对应到真实列的问题变成选列、单位或等级顺序的补充项；其余问题给出选项或一个回答框。回答随研究问题一起交给模型重新规划，已回答的问题不再重复提出，留空的按保守做法处理并写进方案摘要。方案下方列出本次依据的全部说明。平台做不到的分析（如校正协变量）不作为问题提出，在摘要里直接说明。

多个字段的分布由同一步完成：数值给出直方图和描述统计，类别给出频数，已确认顺序的等级按该顺序排列。这是对当前表的描述。

## 多样数据如何逐步进入分析

保留原始材料；读取为可预览的表；识别可验证的结构与候选含义；结合研究问题收集必要补充；仅在算子输入条件满足时生成并执行方案。通用表格可做概览、指定两字段相关和关系表绘图；明确的物种/功能格式由领域工具接入。

今后增加格式时扩展读取适配器、规范化视图和能力契约，不通过为每个用户写死字段名来扩展。不认识或不支持的部分有明确状态，不能由大模型猜成完整事实。
