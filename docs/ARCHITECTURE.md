# 架构与开发

## 分层

```
React 工作区
    │ OpenAPI / JSON / SSE
Flask Blueprint 路由与 Pydantic 请求校验
    ├── 不可变数据导入与映射
    ├── Agent 结构化规划与前置检查
    ├── 报告编辑与导出
    └── SQLite 持久化队列
                    │ 单 worker、原子领取、进程锁
                逐步骤子进程
                    ├── 白名单 Skills
                    ├── 确定性统计与图表
                    └── 受约束的报告解释编排
```

后端模块位于 src/yanji：contracts 定义输入与结果契约；data 处理导入与版本；skills 独立于 HTTP；agent 仅生成计划；worker 管理队列、子进程、取消与缓存；reports 提供报告文档模型和各格式导出；api 处理 HTTP 映射。前端按数据说明、分析设计、快捷工具、结果、报告和连接设置拆分。移除独立聊天侧栏，只保留一个方案认可入口。

## 持久化与升级

SQLAlchemy Record 表保存带类型的版本化 JSON 记录，覆盖 project、dataset、plan、run、event、artifact、report、cache、message 和 model_call。结构化边界由 Pydantic 契约约束。运行、计划、数据和报告分别记录，不能将聊天文字当作已执行操作。

数据库使用 WAL；计划确认绑定输入与样本设置的指纹。领取任务使用 BEGIN IMMEDIATE 保证单项领取，worker 持有操作系统文件锁，避免重复消费。migrations.py 以迁移版本记录执行升级，启动迁移另有进程锁；后续结构调整新增迁移函数，不删除用户库。

## 执行、缓存与取消

每个分析步骤和报告生成都在可终止子进程中执行。主 worker 每隔约三百毫秒检查停止请求；单步骤十分钟超时。服务正常退出终止当前步骤，异常退出后只在核对进程命令与输入路径后处理遗留的自有子进程，运行标为中断，等待用户继续。

缓存键包括不可变数据版本、来源哈希、整理记录、样本配置、Skill 名称、版本和参数。报告始终绑定当前运行；重新执行分析不能覆盖旧报告。修改算法应递增 Skill 版本，使旧缓存失效。

## 模型边界

使用 HTTPX 直接请求 OpenAI 兼容接口。网络异常最多两次请求；无效方案最多两次修正，总共最多三份候选方案。所有步骤必须属于静态注册表，参数由 Pydantic 检查，依赖必须引用前面的步骤，报告为可选末步，快捷任务可只产出计算与图表。

模型只接收研究目标、数据概况、必要结果与 Skills 说明。分组统计摘要可以参与规划，完整样本矩阵不作为提示。阻塞性问题由程序按数据与研究设计产生，模型的可选建议不能造成无休止确认。

初始报告的数字来自计算，可选模型编排只选择已有解释片段。编辑时可另行请求 AI 章节草稿，检查引用 ID 后作为待审核建议返回，用户采用并保存前不会覆盖正文。结构检查不证明语义支持，科学解释与数值仍须审核。修订号用于检测并发覆盖。

## 接口与本地保护

所有业务 API 使用 /api/v1，请求由 Pydantic 校验，前端类型保存在 frontend/src/generated-api.d.ts。提供 SSE 与事件查询，当前工作区使用定时刷新恢复状态。

服务只监听 loopback，Host 与写操作 Origin 受限，禁止跨来源网站调用本地写接口。文件上传只接受表格，产物只通过服务生成 ID 访问，不接受下载任意服务器路径。密钥与模型原始请求不进入产物和日志；调用记录只保留模型、耗时与服务返回的 token 计数。

## 构建和运行

使用 Conda 创建 yj_env（Python 3.12），pip install -r requirements.txt 安装 Python 依赖，npm ci 安装前端依赖。Node 只用于构建前端，python app.py 和 python worker.py 分别启动网页与后台分析。项目不引用 BioFlow 的解释器或服务地址。

在开发中运行 npm 的 dev 命令，Vite 将 /api 转发到本地后端。生产模式由 Flask 提供 frontend/dist，未知 API 不回退为 HTML。

## 字段说明与文献

understanding.py 生成字段画像、预填清楚语义，接收人工说明及可审核的模型建议。保存使用事务与修订检查，并保留独立历史记录。方案、Context 和缓存绑定认可时的语义快照。未知输入保持普通表格，显式重新解释后生成新数据版本。

writing_support.py 提供通用和 ai-localbase 两类文献 API 适配；固定与模型检索有独立轨迹和预算终态。加入报告的来源保留片段、内容哈希与来源级别。生成的章节草稿另存 writing_draft，采用仍需显式编辑保存。按需报告入口与检索/起草请求当前同步处理并设超时，生信数值任务继续由持久化后台 worker 执行。

## 动态数据准备（规划器 3.0）

Step.cohort_from 与 SkillParams.preparation 把队列变换纳入执行契约。preparation.py 的编译、解释、预览与目标检查贯穿生成、回答问题、确认和后台执行；源数据与项目默认分组不被改写。模型生成的旧版 2.0 方案需要重新规划。准备参数及解释器版本进入缓存键，原始版本和审计表进入结果证据。详见 DYNAMIC_ANALYSIS.md。

## 通用程序执行（规划器 4.0）

custom_analysis 使用 AnalysisProgram 明确方法、输入、要求和产物。adaptive.py 负责方案审核、代码生成、静态检查、隔离调度、产物检查、目标审核和有限修复；program_runner.py 是不含应用配置与密钥的计算入口。生成的代码只接收本次输入、输出辅助函数，不接收数据库或模型凭据。worker 取消时终止整个执行进程组，防止嵌套计算遗留。执行失败保留结构化原因。
