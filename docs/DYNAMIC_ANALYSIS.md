# 从研究指令到可执行的数据流

原来的规划器能选择分析工具，却没有派生队列的执行能力。因此“按镁含量上下四分位分组，寻找各组富集菌”会退化为连续相关，改变了研究问题。这是能力和执行契约的问题，不能只靠提示词修复。

现在由智能体选择并组合数据准备操作与分析工具。每个步骤绑定真实文件与字段；后续步骤通过 `cohort_from` 引用前面的 `prepare_cohort`。这不是固定的“四分位分析模板”：同一套准备操作可重新组合，并把结果交给不同的统计或绘图工具。

## 一份方案包含什么

1. 准备队列：按顺序执行筛选、计算派生列、重编码、分位数分组或固定阈值分组。
2. 分析：引用同一队列进行物种差异、多样性、通路差异、组成、核心特征或普通表分析。
3. 输出：记录实际方法、参数、数据版本、样本纳入情况、结果表和图。

例如：先筛选年龄 ≥ 18，再计算两个指标的比值，按比值 P20/P80 建组，然后在这个队列内进行差异分析和各组独立排名。组名、列名、分位点、筛选值、后续分析都由具体研究目标决定，不要求用户修改原始文件。

## 镁含量示例的实际行为

- `prepare_cohort`：绑定实际 Magnesium 字段，生成新的分组列。
- 上下四分位：低组 ≤ P25，高组 ≥ P75，中间区间不参与该队列，缺失和非有限值排除。
- 阈值在所选丰度表匹配到的、未被用户排除、通过前序筛选的样本中计算。
- 使用线性插值分位数；同值不拆分，因此组人数可能不是精确 25%。上下阈值重合时阻断，不任意分派同值样本。
- 确认前展示实际阈值、各组人数和排除原因；不运行统计检验。
- 用户认可后输出逐样本归属、排除原因、派生信息表及准备审计表。
- `differential`：在派生队列上比较两组，输出完整检验表，并分别导出每组 q<0.05、且中位数更高的相对富集候选表。中位数相同不强行指定方向。
- `group_feature_summary`：各组分别计算平均丰度、中位数、检出率及 Top N，分别作图；与显著富集结果明确区分。

这里的富集仍是现有探索性相对丰度差异分析，不是绝对丰度推断、协变量校正或因果结论。独立样本性质由用户确认，重复受试者仍会被阻断。

## 规划与执行的约束

- 规划输出必须通过结构、字段、依赖、队列及统计前提检查。
- 已明确要求分位分组富集时，连续相关方案会被拒绝并要求模型重新设计，不能以“最接近的能力”自动替换目标。
- 请求各组 Top N 时，检查是否确实采用独立的组内排名及对应 N。
- 队列引用必须指向前面的准备步骤，并声明依赖；下游不能另带一份不同的准备规则。
- 预览和执行共用准备解释器；引用关系被编译成每个步骤的不可变准备参数。用户补充独立性回答时保留这些参数。
- 原始文件保留，派生数据属于本次分析；缓存键包含准备规则与解释器版本。
- 登记工具可以准确覆盖时，组合有类型的操作。覆盖不到但数据与当前计算库能够实现时，可使用下述通用程序路径；没有隔离环境时拒绝执行，不回退到裸执行。

## 扩展边界

目前提供 filter、arithmetic、recode、quantile_group、threshold_group 五种准备操作。算术支持加减乘除、log1p，以及与另一列运算。单份准备队列绑定一张已确定样本标识的表。准备操作本身不负责跨表连接或新统计模型，这些任务可走下述通用程序路径，具体方法须分别验证，不能宣称全部已经支持。

可扩展的重点是增加通用操作与明确的数据流契约，而不是为每个自然语言句子追加一个完整分析模板。

实现参考：[pandas 分位数与插值](https://pandas.pydata.org/docs/reference/api/pandas.Series.quantile.html)、[SciPy 独立两样本 Mann–Whitney U](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.mannwhitneyu.html)。

## 通用程序路径（规划器 4.0）

工具目录不再是分析能力的唯一边界。custom_analysis 先声明精确方法、输入文件、逐项研究要求与约定产物。方案审核核对是否忠实于原问题，再生成程序并检查语法和接口；确认前不执行分析。用户可以展开查看待执行程序。

用户认可后，程序在 macOS Seatbelt 隔离环境中运行，只能读取本次导出的输入和安装好的数值库，并写入本次产物目录；不传入模型密钥，禁止网络和派生系统进程。CPU上限60秒、墙钟90秒、单文件64MB；周期监测峰值内存、输出总量和父进程存活。内存监测不是容器硬配额。当前适配 macOS，其他系统需接入隔离后端，不能直接启用裸执行。

允许 numpy/pandas/scipy/matplotlib/skbio 和少量标准数学库。通过 emit_table/emit_chart/check/finish 产出结果。程序接口验证约定行列、全部产物和检查项，再由模型对照原始目标、方法、代码和实际输出结构检查是否遗漏或换题。审核不等于数学正确性证明或专家审核。

失败后最多三次尝试。修复保持方法、比较对象、输入和验收约定，不允许偷换研究问题。成功后保存实际代码、逐项验收和修复历史；失败保留原因，不标记完成。离线复现使用最后通过验收的代码重新计算，不依赖模型连接。

“现有数据可以做的任何分析都一定成功”不能成为保证。依赖、资源、模型可靠性、数据质量和统计假设仍有边界。目标是能够规划、补写程序、修复、核对并解释失败，并持续增加可重复的研究任务验收。

隔离策略参考 OpenAI Codex 的闭合默认 Seatbelt 策略，资源限制参考 Python resource 文档；本项目只开放当前计算需要的更少权限。

参考：[Codex Seatbelt 基础策略](https://github.com/openai/codex/blob/main/codex-rs/sandboxing/src/seatbelt_base_policy.sbpl)、[Python resource](https://docs.python.org/3/library/resource.html)、[DeepSeek 思考模式接口](https://api-docs.deepseek.com/guides/thinking_mode/)。程序生成阶段对官方 DeepSeek 接口显式关闭思考，避免输出额度被推理占满；其他兼容服务不注入该服务专用参数。模型输出截断会明确报错并进入有限重试，不将空输出当程序。


研究工具还可通过 `Step.inputs` 接收上游结果表，和 `cohort_from` 的队列传递分开使用。先筛候选后在全样本回归时只连接候选表，避免把极端组队列带入全样本模型。自定义程序从 `results[alias]` 获取上游表；生成阶段提供已声明的列，执行与修复阶段使用实际表结构。具体输入输出及方法口径见 [biology 方法迁移](BIOLOGY_METHODS.md)。
